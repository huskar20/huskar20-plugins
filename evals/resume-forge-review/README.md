# Evals — resume-forge review

Regression tests for the `review` skill. They exist because the workshop's live
demo depends on the review producing a specific, rich set of findings for two
deliberately bad resumes — a checklist edit that silently changes what the demo
reports would only be discovered in front of the room.

## What is here

- `evals.json` — two eval cases, one per demo resume, each with the prompt to
  run and the findings the review is expected to report. The expectations are
  ground truth: each fixture is generated to fail a documented list of checks.
- `fixtures/` — the two demo resumes. **Fictional people**; every name,
  employer, school, address, and phone number is invented.

`Demo_BadResume_JordanBlake.docx` is plainly bad (passive bullets, a skills
table, 9pt text, no LinkedIn). `Demo_BadResume_DevonMarsh.docx` is the
over-designed one (sidebar, photo, star ratings, an unclaimed default LinkedIn
URL) — it looks impressive and fails almost everything.

## Running

Each eval is one run of the review skill: give Claude the prompt from
`evals.json` (file paths are relative to this directory), let it work through
`plugins/resume-forge/skills/review/`, then check the output against the
`expectations` list. The expectations are semantic — "reports the ALL-CAPS
name" — so grade them by reading the review, not by string matching. The
skill-creator skill's eval loop automates the run/grade/compare cycle if you
want the full benchmark treatment.

## Keeping it honest

- The fixtures are generated by the workshop kit's build scripts (kept outside
  this repo). When the demos are regenerated, copy the fresh files in and
  re-check the expectations against the build scripts' documented failure
  lists.
- When the checklist gains or loses an item, update the expectations here in
  the same pull request — this directory is the tripwire, and a stale tripwire
  is worse than none.
